## 경민 — simulator

- **The simulator now has a spec before it exists: `docs/INTERPRETATION_CONTRACT.md`.** Phase 0 is built *to* it: six-primitive task programs (a TIMER primitive was added for drift-free periodic wakes), a canonical input format with a two-op event set, and one governing rule — *compile time resolves all randomness; run time resolves all timing that scheduling can influence*. The simulator is RNG-free; all sampling happens in the dataset compiler.
- **Single core is now decided, not leaned** (Q1 of the archived open-questions record). We examined multi-lane seriously and rejected it — the blast radius (EDF loses single-core optimality via Dhall's effect, fill-K executor semantics, tuning-pool redo) is in the grill record if you want the reasoning. The multi-core-measured archetype numbers are reconciled by a lane-scaling compile pass plus a demand-budget rule (building plan §5a) — nothing lands on the simulator side.
- **First integration test is defined** (contract §8): one C1 workload end-to-end. If anything in the contract fights the DES design you have in mind, flag it **before the compiler is built** — after that, changes cost double.

## 이안 — recognition & whitelist

- **What the recognizer will consume is now concrete:** canonical folds with multiplicity annotations (`chrome (25 procs)`), names only. Chrome is the default browser binding; renderer multiplicity is parameterized from tabbed-browsing literature against the Chromium process model (see `dubroy-chi10` / `chang-chi21` / `mozilla-testpilot10` in REFERENCES.md).
- **The familiarity ladder (building plan §3, C5)** includes two *nonexistent-name* tiers where the whitelist scores structurally zero — and C1 is deliberately the whitelist's home ground where it should win. Three C6 files are pre-committed misses (name-collision spoof, fold-internal change, dual-active ambiguity) — they're scope boundaries, not bugs to fix.
- **Citation discipline for anything you write:** `docs/REFERENCES.md` owns citations and the id rule; the recipe is in its header. Every entry is verified against a primary source — several of our informal attributions turned out wrong (details in the vetting doc's rev.3 notes), so don't cite from memory.
