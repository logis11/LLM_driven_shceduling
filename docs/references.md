# REFERENCES — master citation index
> Status: normative · Created 2026-08-26 · Updated 2026-10-16

The single index answering "what do we cite, in what form, for what claim." One id namespace across the whole project: these ids are the `source:` tag prefixes in the dataset (via `dataset/sources.yaml`) and the bibkeys in the paper. This file owns every citation string and every citation-constituent field (`url`, `accessed`, `pinned_version`); the yaml registry holds machine/derivation fields only and must be a subset of this index (lint: every yaml id has an entry here; entries here without a yaml counterpart are paper-only references).

## Id-minting rule

**Entry unit: one citable artifact** — the thing that gets exactly one citation, one URL, one accessed date. A project with several citable artifacts (paper + slides + repo) gets several entries.

Id derivation by `type`:

- **scholarly** → `<label>-<venue><yy>` — label is the first-author surname, or the system name when the work is universally known by it (`cpsmark-tbench23`, `ghost-sosp21`). arXiv-only works use `arxiv` in the venue slot (`focal-arxiv26`). Raw arXiv numbers are banned as ids — they live in the citation.
- **deployed-system** → project name, no year; `pinned_version` carries freshness (`interbench`, `rt-app`, `steam-downloads`).
- **talk, conference abstract or news report** → `<label>-<venue><yy>` — label is the speaker's or author's surname, or the system's name (`lavd-ossna24`, `corbet-lwn24`). Its claims are the speaker's or reporter's, stated as theirs; a number it carries is stated only as its report, with its date.
- **measurement** → `meas-ci`, with campaign identification in the locator (`meas-ci:<workflow>:<campaign>`): the campaign is the launch date of its first batch (`YYYY-MM-DD`), a letter added for a second campaign of the same workflow launched that date (`YYYY-MM-DDb`); its runs may be several, each repeat's run id recorded in the pooled record, and its raw records are one release (the 9.5 campaigns of 2026-09-18 to 2026-09-20 share releases, one of them spread over two; `dataset/meas-releases.yaml` maps each campaign the data cites to its releases). A single run number (`meas-ci:<workflow>:<run>`) identifies a campaign of one run from before this form. A measurement on a named local machine is `meas-local`, its locator `meas-local:<machine>-<subject>:<date>`, the date the run started (UTC) as for a `meas-ci` campaign: its raw records are one release with the machine's hostname removed, the machine's specification is stated with every figure, and its spread over its repeats is reported.

**Contributor recipe:** (1) read this rule and mint the id; (2) add the entry here; (3) add a `dataset/sources.yaml` entry *only if the dataset derives values or structure from it*.

## Citation-tier rule

- **scholarly** → numbered bibliography. May support empirical, behavioral, and statistical claims within its stated role.
- **deployed-system** → footnote with URL + accessed date + pinned version. Supports existence claims ("this scenario/setting/category exists in shipped software"); the system's own documented design or behaviour, stated as that source's at its pinned version or accessed date ("the kernel's documentation states …"); and a figure the source publishes, stated as its report with the date read, the window and how it is computed. Never a behavioural or statistical claim stated as the paper's own or as a population's.
- **talk, conference abstract or news report** → footnote with URL + accessed date. Its claims are stated as the speaker's or reporter's, never as the paper's own; a number it carries is stated only as its report, with its date.
- An entry's `role:` line states what claims it may support; do not cite outside the role.

Status legend: `verified` (coordinates confirmed against primary sources, date given) · `to-pin` (identification certain; exact URL/version to pin before submission) · `provisional` (identification incomplete — do not cite until resolved).
