### C-pcmark-5 — does the guide document per-process or per-task timing?

**(a) Verbatim**

App Start-up, PDF p.50: "For each application in the warm start part of the test: 1. Start the application. 2. Measure the time taken until the application is responsive. 3. Close the application. 4. Repeat from step 1 five times. 5. The result is the geomean of the five runs."

p.51 result table (excerpt): "𝑅1 Writer warm start s 0.9-1.8 / 𝑅2 Writer cold start s 3.0-8.0 …"

Writing, PDF p.63: "The workloads measure the time it takes to load the documents, save the file, add pictures, and edit the document."

PDF p.63: "In the copy and cut tests, the operation is repeated ten times to reduce random error. The secondary scores described in the Workload sub-chapter are then based on the geometric mean of the ten repeats."

Photo Editing, PDF p.74: "The load time of the files is the following measurement: dbg_photo_load_cpu. The resize time of the files is the following measurement: dbg_photo_resize_cpu."

Storage, PDF p.112: "During a trace playback, the start and end time is measured for each I/O."

PDF p.123: "With this setting, a file for each trace playback is produced listing the measured timing for every single I/O executed during the playback."

Monitoring, PDF pp.34–35: "Temperature shows how CPU temperature and GPU temperature changed during the benchmark run." … "Power Consumption shows how CPU power consumption changed during the benchmark run."

**(b) Locator.** PDF pp.50–51, 52–56, 63–65, 66–69, 72–75, 112, 123–128, 34–35.

**(c) Reading.**
- **Per-task timing: documented.** Each workload lists its scripted tasks and the timed quantities: load, save, copy/paste, recalculate, app start until responsive, and per-filter times. Each timed item has a named internal measurement, e.g. `dbg_pcm10_writing_save_document_as` (typeset in math-italic in the PDF) or `dbg_photo_load_cpu`. Tables give units and typical ranges on reference systems. Storage benchmarks go further and log per-I/O start and end times.
- **Per-process timing: not documented.** Searching the extracted text for "process", "per-task", "timestamp", "trace" and "per task" found no per-OS-process timing. That means no process CPU time and no per-process scheduling or latency data. Hardware monitoring is system-wide (CPU/GPU temperature, frequency, CPU power, GPU load, battery). The only "process" hit that touches the OS is a release-notes line (v2.1.2165, p.131): "avoid PCMark 10 tests being classed as background processes".

**(d) Verdict: PARTIAL.** Per-task timing FOUND. Per-process timing NOT FOUND (searched the full 141-page text as described).

### C-sysmark30-5 — does the guide separate scenario descriptions from scoring? And the 2011 vendor departures from BAPCo with stated reasons

**(a) Verbatim**

*Part 1, user guide v1.2.*

PDF p.5 (Introduction): "This document is intended as a user manual to assist with the installation, configuration, and execution of SYSmark 30. For a technical overview of SYSmark 30, please download the SYSmark 30 Whitepaper published on the BAPCo website: www.bapco.com"

PDF p.33 ("Reference system"): "SYSmark 30 performance scores are normalized using a reference system. The reference system scores '1000' on each of the three scenarios, and on the overall SYSmark 30 performance rating."

PDF p.38 (Full Disclosure Report, rules): "SYSmark 30 Overall rating will only be generated when all 4 s cenarios are performed." (the space inside "s cenarios" is in the extracted text)

Scoring formulas are only in the whitepaper, §2.4, PDF p.15: "The overall score is produced only if all four scenarios are executed and is calculated by taking the geomean of the four scenario ratings."

*Part 2, AMD press release (primary), 21 June 2011:*

> "AMD (NYSE: AMD) today announced that it will not endorse the SYSmark 2012 Benchmark (SM2012), which is published by BAPCo (Business Applications Performance Corporation). Along with the withdrawal of support, AMD has resigned from the BAPCo organization."
> "'Technology is evolving at an incredible pace, and customers need clear and reliable measurements to understand the expected performance and value of their systems,' said Nigel Dessau, senior vice president and Chief Marketing Officer at AMD. 'AMD does not believe SM2012 achieves this objective. Hence AMD cannot endorse or support SM2012 or remain part of the BAPCo consortium.'"
> "AMD will only endorse benchmarks based on real-world computing models and software applications, and which provide useful and relevant information. AMD believes benchmarks should be constructed to provide unbiased results and be transparent to customers making decisions based on those results."
> "For more details on AMD's decision to exit BAPCo, please read AMD's Executive Blog authored by Nigel Dessau."

TechSpot, 23 June 2011 (secondary):
> "Interestingly, AMD is not the only defector, as Nvidia and VIA have also decided to leave the consortium. Echoing AMD's sentiment, VIA said it wanted a more open and transparent process for developing fair and objective benchmarks that accurately measure real world performance, while Nvidia declined to comment on their reasons."
> "'The heart of our complaint is this: the SYSmark benchmark is not only comprised of unrepresentative workloads (workloads that ignore the importance of heterogeneous computing and, frankly, favor our competitor's designs), but it actually generates misleading results that can lead to very poor purchasing decisions,' AMD's chief marketing officer Nigel Dessau wrote in a blog post."
> "For its part BAPCo is defending its 2012 benchmark, noting that AMD participated in its two-year development, and lamented that the latter had 'once more violated the confidentiality agreement it signed in an attempt to dissuade customers from using SySmark to assess the performance of their systems.'"

**(b) Locator.** User guide v1.2 PDF pp.5, 33, 34–35, 38. Whitepaper v1.2 §2.4 PDF pp.14–15. AMD IR press release 368 (body). TechSpot article paragraphs 4–7.

**(c) Reading.**

Part 1: Yes, the user guide keeps them apart.
- Scenario descriptions are in "Scenarios" (pp.34–35).
- The guide has no scoring methodology. It only says scores are normalized to a reference system (p.33) and points readers to the whitepaper for the technical overview. The formulas (scenario rating = calibration run time / SUT run time × 1000; overall = geomean of four) are only in the whitepaper §2.4.
- Inconsistency: user guide p.33 says "each of the three scenarios" although there are four. The same sentence is in v1.1.

Part 2:
- AMD's primary release (21 June 2011) confirms it resigned from BAPCo and would not endorse SYSmark 2012.
