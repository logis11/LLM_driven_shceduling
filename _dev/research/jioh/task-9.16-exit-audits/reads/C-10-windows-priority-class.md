**Passages.**
- "The priority of each thread is determined by the following criteria: The priority class of its process; The priority level of the thread within the priority class of its process. The priority class and priority level are combined to form the base priority of a thread."
- §Priority Class: "Each process belongs to one of the following priority classes: IDLE_PRIORITY_CLASS, BELOW_NORMAL_PRIORITY_CLASS, NORMAL_PRIORITY_CLASS, ABOVE_NORMAL_PRIORITY_CLASS, HIGH_PRIORITY_CLASS, REALTIME_PRIORITY_CLASS. By default, the priority class of a process is NORMAL_PRIORITY_CLASS. Use the CreateProcess function to specify the priority class of a child process when you create it. … Use the GetPriorityClass function to determine the current priority class of a process and the SetPriorityClass function to change the priority class of a process."
- §Priority Class: "Processes that monitor the system, such as screen savers or applications that periodically update a display, should use IDLE_PRIORITY_CLASS."
- §Priority Level: "All threads are created using THREAD_PRIORITY_NORMAL. This means that the thread priority is the same as the process priority class. After you create a thread, use the SetThreadPriority function to adjust its priority relative to other threads in the process." … "Background threads, particularly those that are processor intensive, can be set to THREAD_PRIORITY_BELOW_NORMAL or THREAD_PRIORITY_LOWEST, to ensure that they can be preempted when necessary."

**Reading.** A Windows process has a priority class and each thread a priority level within it, combined into the thread's base priority; a program sets its own class (`SetPriorityClass`, or `CreateProcess` for a child) and its threads' levels (`SetThreadPriority`), the page naming `IDLE_PRIORITY_CLASS` for monitoring processes and the below-normal levels for background threads. The restated sentence and the table cell hold; no doc change.
