## Findings that bear on a premise

- **The stock Ubuntu 24.04 desktop ships none of the unasked jobs the counterparts use** (S2-01, S4-03: the 24.04.5.1 image's manifests): ClamAV, plocate, DKMS, gcc and make are in neither install selection; Tracker 3.7.1 is in the default one because GNOME Files depends on it (S2-02); Déjà Dup only in the extended one, its periodic backup off by default (S2-03, S4-05). ClamAV's packages ship a signature updater (`freshclam` as a daemon, or a daily one-shot timer) and a scanner daemon, and "no scheduled scan is shipped" (S2-03). DKMS's kernel hooks run `dkms autoinstall` on a kernel or headers install (S2-03, S4-07), and on Ubuntu the recommended NVIDIA route installs prebuilt signed modules, so a kernel update triggers no NVIDIA DKMS build unless the user chose the DKMS packages (S2-28).
- **The jobs it does run unasked**: 15 enabled system timers — `anacron`, `apport-autoreport`, `apt-daily`, `apt-daily-upgrade`, `dpkg-db-backup`, `e2scrub_all`, `fstrim`, `fwupd-refresh`, `logrotate`, `man-db`, `motd-news`, `snapd.snap-repair`, `ua-timer`, `update-notifier-download`, `update-notifier-motd` — with schedules in the units (S2-03, S4-03); sysstat's 10-minute collector wired in although its switch says off (S4-05, an inference from files); snap refreshes four times a day (S2-08). Observed durations are single-machine journal excerpts (S3-35). `dpkg-db-backup` is a daily backup the system runs unasked under its own name (S2-03 quotes the unit and the script).
- **A desktop's indexer re-crawls in full rarely by design**: Tracker 3.7 crawls at each start and compares every directory's mtime against the database only after an unclean shutdown, or always when `crawling-interval` is 0 (S2-04); observed full re-indexes are regressions or kernel-update effects (S3-36, S3-37).
- **SYSmark 30 defines a photo/video overlap, not a sequence**: in Advanced Content Creation "A video encode is started in Adobe Premiere and sent to the background while Adobe Photoshop is launched and used to manipulate photos in the foreground"; Outlook "remains open throughout the scenario for ambient load" in Office Applications (S2-15). Procyon's Office Productivity runs Word, Excel, PowerPoint and Outlook "running simultaneously as the focus moves from one task to another" (S2-14).
- **Teams on Linux is a browser web app** (S2-26), so a Teams call is the browser's processes; Chromium names its call threads `WebRTC_Signaling`, `WebRTC_W_and_N`, `AudioOutputDevice` and runs its audio service in a separate process on Linux (S2-16).
- **Wine renames each process to its `.exe` name, and Windows thread names become Linux thread `comm`s** (S2-18), which the game listings show (S3-20, S3-24, S1-62, S1-63).
- **Nested gamescope's cadence is the host's**: the vblank timer runs at `--nested-refresh` if given, otherwise the output refresh, initialised to 60 Hz and then set from the desktop display (S2-21); observed readouts follow the host refresh (S3-29).
- **Chromium's process model on desktop Linux**: one process per site, a soft process limit of installed RAM / 2 ÷ 85 MB clamped between 3 and half the platform limit, one spare renderer kept (S2-16). No class found a renderer listing for a stated tab set on Linux.
