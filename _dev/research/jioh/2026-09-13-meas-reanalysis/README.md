Release `meas-ci-2026-08-28` (cli:3 run 33144766132, gui:2 run 33139471432) re-analysed with `dataset/tools/meas/analyze.py` as fixed in task 9.3. Spec: `_dev/docs/spec/jioh/task-9.3-measurement-tools.md`. Defect numbers (#n) are those of `_dev/research/jioh/2026-09-13-verification/meas-report.md`. `dataset/meas/summary.json` is unchanged.

## Files

- `summary.json` — the corrected summary, same layout as `dataset/meas/summary.json`. Produced from `_dev/research/jioh/2026-09-13-verification/meas/` with `analyze.py run_cli3 --json summary.json` (raw release data local only; see that folder's README).

## What the fixes changed

| # | Tool | Change | Fields |
|---|---|---|---|
| 1 | `analyze.py` | The compiler child is `cc1` (`CHILD_NAMES`), not every compiler-family process. The family is reported separately. | `compiler[_cold]_{lifetime, children, cpu_mean_us, life_mean_us, peak_concurrent}` now describe cc1; new `compiler[_cold]_family_exits`, `compiler[_cold]_family_peak_concurrent` |
| 12 | `analyze.py` | `make`'s CPU is divided by the forks `make` itself makes, not by compiler-family execs. | `make_dispatch_us`, `fork_rate_hz` (make's forks per second); new `make_children` |
| 5 | `analyze.py` | Chromium wake statistics cover renderers only: pids whose own `lifecycle.log` lines carry `--type=renderer`. | `chromium_wakes`, `across_repeats.chromium` |
| 9 | `analyze.py` | Zero values stay out of the log fit, and are no longer silent: `p90_us` is taken over the same positive values, and `n_nonpositive` with `median_all_us` (plain median over all values) appear beside any fit that had zeros. | `daemons.work`, `chromium.work` |
| 3 | `proc_sampler.py` | With `--ctxt`, also `tctxt` {tid: [voluntary, nonvoluntary]} from every `/proc/<pid>/task/<tid>/status`; `analyze.py` sums per-thread deltas when present. | new `across_repeats.wake_counter` (`main-thread` for this release) |
| 14 | `verify_names.py` | `runtime` only when the catalog name itself is seen (comm = name cut to 15 characters, or argv0 = name); binaries include `/sbin/`; snap stub scripts are not binaries; a package with no binary is `package-no-binary`; `run_attempted` recorded. | name tables of future `meas-names` runs |
