## Decisions

1. **Structure kept, content replaced.** The 13 sections and the study-doc voice stay; §4's families are regrouped by what the entries are (W-0161 left the grouping to the editor). §5.6 kept as a one-paragraph section rather than deleted, so the old reader finds where the native mode went.
2. **Blocked TIMER text untouched.** Per spec decision 9 and W-0189, the primitive table's TIMER row, the TIMER/SLEEP paragraph, and the backlog sentences in `c3-evening` and §12 stand verbatim. New TIMER sentences say only which tasks carry TIMER and what t₀ is — neither is the backlog/skip rule.
3. **t₀ wording.** W-0183's change text says t₀ "cannot come apart from the arrival silently", and `dataset/tools/wlc/linter.py:359–360`'s comment says t₀ "is the task's arrival"; `docs/harness/metrics.md` §6.2 says a head arriving on a busy lane runs its first TIMER later than it arrives, and `simulator/src/sim.cpp:674` sets t₀ at the first TIMER execution. Wrote: t₀ = first TIMER execution = the task's first dispatch, later than arrival when the lane is busy. The linter comment is a found row (below). Mid-run TIMER count recounted: 23 TIMER tasks, 4 arriving mid-run (`c3-evening` ×3, `c6-fold` ×1) — 9.11 D32's 22 predates `c6-fold`'s call.
4. **C3 boundary count.** W-0180's final word says "about eight boundaries"; the three arcs have 3 + 2 + 2 = 7 segment boundaries. Wrote 7.
5. **DKMS `objtool`.** W-0163's final word carries 9.6 D37 ("the DKMS job has seven members, objtool too"). The module build of 9.10 (`module-compiler-child`'s trees and modeling notes) folds `objtool`'s CPU into `sh`; the compiled `c7-compile` has no `objtool`. Code wins (and 9.10 D53 is the later record); wrote the fold.
6. **`c6-dual` "outside grading and scoring".** The code: the grader skips `ambiguous` segments (`grader.py`), the oracle falls back by construction, the scoring spec still carries two terms, and the RQ0 gate spec makes the file reporting-only and excludes C3–C6 from Layer-2 aggregation. Wrote that, not "outside scoring". Logged below as a wording difference.
7. **P1 headroom "measured as zero".** W-0168's final word reads 9.23 D9 as "measured as zero"; the RQ0 gate spec's `idle-class-files` statement gives it as a prediction from the strict idle rule before any run. Wrote it as a consequence of the rule (no row can move the idle-class side), which is what the gate spec states.
8. **What the simulator sees.** The old table said the simulator does not see names; the run file keeps `name` (data-contracts' run-file definition removes only `ground_truth`, `focus` and most of `meta`), and `sim.cpp` reads child names. Wrote: names are in the run file but no scheduling decision uses them.
9. **Scenario catalog description.** Aligned §2 with existence-only grounding (9.10 D2, as the wave-1 catalog rewrite states it): each row grounds the scenario and names' existence; which share a segment is design. S1/S18 named "office"/"session process"; bare S-codes in C4/C6 spelled out.
10. **Old mock references.** "Phase 5의 mock 1/2/3번" → the fixtures `mock-office`, `mock-media`, `mock-p1a` under `harness/tools/tests/fixtures/`, described as `docs/harness/metrics.md`'s fixture list does.

12. **Retirement reason.** W-0737's answer requires docs restating the retirement to carry 인지오's reason; §8 does, as a statement of the design, not a debate.
13. **Old open items.** `random`'s draw closed by the code (the mock daemon draws uniformly over the driver table's rows); the familiarity-annotation item restated as fact (annotations in C5 and the generated ladder only); the `demand: calibration` item folded into §8; `wineserver` provisional and t₀ removed (W-0158, W-0183).
