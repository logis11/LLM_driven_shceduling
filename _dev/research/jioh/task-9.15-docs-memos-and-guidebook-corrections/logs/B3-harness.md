## Decisions

1. **The arrival reaches the aggregates as a records row, not as an argument from the trace.** The aggregates are computed from records alone (the code: `compute_aggregates(rows)`, `score.py` from records files, `mock-scores` hand records with no trace; metrics §8; the records README), so the trace's `task_arrive` time has to be in the records for every path to agree. The other way — the runner passing the trace's arrivals into `compute_aggregates` — would leave `score.py` and the records-only fixtures on the `arrive`-row reading, the same run giving two aggregates files. The row is a lifetime row at `T_end` with the arrival as its value, beside `demand` (a per-task fact at `T_end`). The records gain a metric value, not a column (still twenty-five). Question for 인지오 below.
2. **(h)'s clauses are what the runner uses, not the whole of contract 10**: no gzip clause (the runner's trace path is `trace.jsonl`); the version cross-check is in, since the pipeline refuses a trace whose `sim` differs (`runner.py:306–309`).
3. **The boost grid restarts only inside the MLFQ intervals the harness already reports** (entered by a switch, §6.10's scope); a boot MLFQ interval still gets no boost rows. A boost instant at exactly a same-algorithm entry's applied time is not a boost (the entry applies first and voids the timer: same-µs config entries first, D1; the epoch bump).
4. **`mock-p1a`'s narrated boost removed rather than kept as the mock's own grid**: the fixture states its MLFQ as the simulator guide's rules with metrics §11's entries, and item 9 now includes the restart.
5. **Metrics §9 left unchanged** to keep vol-05's verbatim quote exact (above).
