1. **The catalog's general clause is kept.** "A generated segment carries the tags of the C1 segment its task set comes from … and adds those of another placement's programs alive in it" describes `compose_full` (transition grid, return grid, flap-stress); the distractor's second segment is stated in its own sentence, which now gives the rule rather than an exception. The brief says nothing else changes.
2. **The catalog names the four modes and the count.** The old sentence did; the new one says why the tag leaves (no other program of A's shows it), checked against the C1 timelines, so a reader does not take render or compile, whose batch jobs also lack `depart`, for cases.
3. **The building plan's bullet uses parentheses, not dashes,** because the clause sits inside the bullet's existing dash pair. No pointer to the generator test or to the catalog was added (the brief: nothing else).

### Findings (minor)

1. **`docs/workload/scenario-catalog.md:8`: the clause before the edited sentence is now narrower than the code.** The clause says that "a generated segment carries the tags of the C1 segment its task set comes from (9.19 spec, decision 3) and adds those of another placement's programs alive in it". That is unchanged text, and it is phrased as covering every generated segment. A distractor cell's second segment is labelled A, and A's task set fills it. Yet in 68 cells it no longer carries all of A's C1 tags (`dx-backup-with-7z`'s second segment drops S15). The next sentence states the distractor case correctly, so the paragraph read whole is accurate. The general clause, though, describes only `compose_full`: the transition grid, the return grid and flap-stress. The log's decision 1 keeps it for that reason, but the doc does not say so. A one-phrase scoping would remove the tension, e.g. "a transition, return or flap-stress segment carries …", or "a generated segment's tags name the programs alive in it: …". This is the same narrowing the B4 review noted in `_compose_distractor`'s docstring.
