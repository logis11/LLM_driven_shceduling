## Decisions

1. **W-0855's optional lint is a data test, not a loader check.** A check in `_load_operations` would reject `test_operation_replaces_components_for_its_measured_duration` (`test_measured.py`, an operation in a timeline with no `input` track) and `test_replay_compile.py::test_an_operation_keeps_its_precedence_over_the_replay`, compile-mechanism tests that place an operation without a keystroke window; giving them windows would change the keystroke streams they assert on. The test over the committed core set holds the rule where the data is, reaches no manifest, and the docstring says where the rule is held.
2. **W-0890 applies 9.10 D168 as the code states it, giving the row's 214.** D168's text and `test_every_segment_tags_the_scenarios_of_the_programs_it_shows` count a task with no `depart` (a batch job) in the segment its arrival falls in. In the `focus` form A's batch job is scaled to the 118 s it is alive in but has no `depart`, so it counts in the first segment only: 214 files gain a tag under this rule; with every one of A's C1 tags added it would be 226 (the twelve where only A's batch job's tag is new: A ∈ {backup S15, indexing S14, ml-train S12, transcode S8} against a B that carries none of A's other tags). The row's and K02's M8's 214 is the coded rule's count, so that rule is taken. The map lives in the generator (an input of the generated manifests); the generator test checks the composed files with `test_coreset`'s own copy, so the two cannot drift silently.
3. **W-0900 and W-0901 change the fold-ins, not only the library.** The library's measured entries are the fold-ins' output byte for byte (`test_meas.py::test_the_fold_in_regenerates_the_nine_entries_from_the_pooled_records`, `test_meas_desktop.py::test_the_fold_in_regenerates_the_library_s_entries_from_the_pooled_record`); the sentence comes from each control record's `notes` (`control_report.control_notes`), and the records are under `_dev/` (spec decision 11). So `dataset/tools/meas/control_report.py` gains `CONTROL_RAN` (per entry, (old, new) pairs) and `fold_reading`, and `campaign/fold_in.py` and `desktop/fold_in.py` pass each record reading through it on `--control`; the library's ten entries were rewritten with the same pairs and the regeneration tests pass on them. `control_notes` and the records are unchanged (`test_meas_control.py:527` holds a record's `notes` to `control_notes`). A reading without the named text passes unchanged (the fold-in tests' stand-in readings); the regeneration tests are the guard that the real records' text is matched. New test `test_the_library_s_readings_name_only_the_phases_the_control_ran`: the ten entries carry the scoped clause, the six others "every carried phase", and the ten are exactly the entries with a `launch` param.
4. **W-0898's two values are four table rows,** a gap and a run each, as `Chrome_ChildIOT` is carried; the wake rate is the gap's reciprocal and has no table of its own. Source strings in the form of `Chrome_ChildIOT`'s.
