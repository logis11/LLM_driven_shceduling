## Decisions

1. **W-0986's optional `:115` part is applied.** F3's reviewer held it unneeded because `:117` states the queued entry. Against the code, `:115`'s exception list ("each entry takes effect at its `t_us` … unless it is a switch that drains") leaves out an entry stamped while a switch drains, which `on_config_apply` queues (`:574`) and which does not take effect at its `t_us` (run above: index 2 stamped 36000, applied 50000). Under spec decision 3 the sentence describes the code.
2. **W-0987 is applied, in wording broader than N3's draft.** N3's draft read "if it is ever woken and its next instruction is a RUN". The code's condition is wider: `on_unblock` advances past the WAIT and calls `step`, which passes a WAKE, a FORK below its cap, a LOOP head or end, a TIMER whose tick has passed and a WAIT with a stored wake without blocking, and the task is enqueued with `ready` only if `step` settles on a RUN (`:657–716`, `:800–806`). The run above shows a WAKE between the WAIT and the RUN keeping the `ready` line at the wake, and a SLEEP there moving it to the sleep's end. So the sentence reads "the instructions after that WAIT reach a RUN without blocking or ending it". No data claim is added: in the core set a RUN directly follows every such WAIT but in 4 lone-WAIT programs (scan above), so the scope changes nothing for the files.
3. **The citations follow the file's own form.** `simulator/src/sim.cpp:<line>` with bare `:<line>` after the first in a paragraph, as §6 and §9.2 already cite it. `on_unblock` is named as `on_arrive`, `spawn` and `step` are in the same paragraph.
4. **"Under MLFQ" only.** Only MLFQ's `start` arms a policy timer (`:210`; FIFO's `start` is empty at `:169`, EDF's at `:288` and LOTTERY's at `:355` arm none), so the restart is stated for MLFQ alone.
5. **§3's End rule (`:113`) is left as the contract states it.** The reference simulator applies and traces entries at or after the workload's end (`sim.cpp:540–545`, `:937–967`), against `docs/data-contracts.md` §7's **End** rule. 인지오's answer (b) to N1 (2026-10-17) keeps the contract and the harness unchanged and has the final memo name the difference (W-1002). The guide states the contract's rules as what the simulator must do, as it states the strict idle class (`:71`), which the simulator does not read either; no edit.
6. **"Queue levels are kept" (`:117`) is left as written.** The simulator clamps a level to a smaller `num_queues` (`:209`), which metrics §11 item 9 states. The guide's sentence is a summary that is not contradicted by the clamp; no row.
