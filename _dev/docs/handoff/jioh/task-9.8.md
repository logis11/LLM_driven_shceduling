## The one-observation situation

`electron-comms` rests on `meas-ci:gui:2`'s Element phase, whose two values are the geometric centre between an idle unauthenticated Element's main process (gap 0.40–0.43 s) and its GPU and network helpers (3.84–3.92 s), with no renderer in the tree (X4), and whose OQ-3 referee compared fifty `chrom*` processes of every role against them (X5). The search found no external observation that grounds the archetype whole, and none that grounds any bound program as a per-wake distribution:

- **Chrome renderers.** Linux evidence is prose readings in the Chromium tracker with the tables and traces behind sign-in (S3-01: "> 60" wake-ups/s per process idle on `chrome://about`, Chrome 46; S3-02: "> 270" idle wake-ups/s on one loaded page, Chrome 78; two background-tab pathologies) and a 2017 count of tabs before renderer sharing (S1-18: 31 at 4 GB, ≈ 70 at 8 GB, Chromium v53). The mechanisms are fully fixed from Chromium source at one commit (S2-01…S2-07): site-per-process on desktop Linux; the soft process limit (half of RAM ÷ 85 MB, 96 on a 16 GB machine); a hidden renderer set to nice 5 only when the browser can re-raise it, otherwise untouched; hidden-page timers aligned to 1/s, then 1/min after five minutes, 3 ms per throttled wake, a 1 % CPU budget; freezing off on desktop; Memory Saver discards at 2/4/6 h. The Windows field data (S1-01: renderer count p50 6.2, p99 52.7; per-renderer CPU p99 31.8 %) is context.
- **Comms clients.** Zoom idle at 2–7 % of a core across several Linux reporters and a fleet average of 7 % (S3-10); Discord idle as a whole-laptop draw (S3-12) and 35–45 % in a voice channel (S3-13); Element web at 5–15 % in a background Firefox tab (S3-15); one paper with in-call CPU pooled over Slack, Discord and Skype on Ubuntu (S1-07: 15.9 % of four cores against 14.3 % in Chrome); Slack on Linux nothing. Protocol cadences from source: Discord heartbeat every server-assigned interval (documented example 45 s, S2-10), Matrix `/sync` long-poll 30 s (S2-12, S2-13), Slack "every few seconds" (S2-11). No wake cadence or CPU per wake for any of them.
- **Steam.** Idle: + 0.5 W on a laptop and a `steamwebhelper` thread polling every ≈ 5–6 ms (S3-22); ≈ 25 % of a core minimised on the Store page and 0–1 % with `-no-browser` (S3-25). Behind a game: one `ps` snapshot ≈ 7 min into a Proton game with `gameoverlayui` at 0.6 % and `steamwebhelper --type=renderer` at 0.0 % (S3-28); five client processes at 20–30 % each with a hidden chat window (S3-23, 2020 beta).
