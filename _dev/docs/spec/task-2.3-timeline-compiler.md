# Task 2.3 — Timeline→canonical compiler, linter, invariant tests

Fixes the base timeline format and the compiler/linter contract. Parent: `2.3` in `_dev/TODO.md`; phase spec: `_dev/docs/spec/phase-2-workload-dataset-generation.md`. Authoring sugar (`variants:`/`inherit()`/`inject:`) is out of scope — fixed in 2.4's session.

## Scope

- The timeline→canonical compiler (`-native` and `-single` modes), the lane-scaling compile pass, the per-file static demand estimate, the linter, the invariant test suite, and the GitHub Actions wiring.
- Tooling: Python under `dataset/tools/`, pytest, `make dataset` / `make lint` / `make test`; compiled output under `dataset/build/`.

## Locked decisions

### 1. Timeline format: three independent tracks

A timeline is `meta:` plus three top-level tracks — `segments:` (time ranges with mode + attributes; becomes `ground_truth`), `tasks:` (process bindings; becomes `events`), `focus:` (the user's single input-attention track). The split mirrors the canonical `ground_truth`/`events` separation.

### 2. Task entry

Fields: author-chosen stable `id` (canonical task ids derive deterministically from it), `name`, `archetype`, `arrive`, `depart` present iff segment-bound (lifetime class implied, linted against the archetype's `lifetime`), `bind:` restricted to keys the archetype declares in `binding_params` (any other numeric is the inline-numerics lint violation), `count:` for static multiplicity (expands to N per-instance-sampled tasks). Times/durations are human-suffixed strings (`50ms`, `8m30s`), normalized to integer µs.

### 3. Focus track

`focus:` is a single timeline-wide list of `{from, to, task}` windows; overlap is impossible by construction, gaps mean no one receives input. The compiler samples input wake events from the focused task's archetype gap distribution inside each window. Focus may only target tasks whose archetype has an input channel — linted.

### 4. Segments carry scenario annotations; the compiler reads two inputs

Segment entries may carry an optional `scenario:` list of S-ids — compiler-ignored, linter-read (coverage-grid reporting, traceability). The scenario catalog stays prose; the compiler's only inputs are the timeline and `archetypes.yaml`.

### 5. Seed and keyed substreams

The seed lives in the timeline's `meta:`; a timeline is self-contained and `timeline@commit + archetypes@commit` reproduce the bytes. Sampling uses keyed substreams derived from `(seed, task id, param, draw index)` — never one global draw sequence — so unrelated edits cannot shift another task's draws and C2 byte-identity holds by construction.

### 6. Build outputs: lockfile pattern

`dataset/build/` is gitignored; a committed hash manifest (per-artifact content hashes + the input commits they derive from) is regenerated by `make dataset` and verified by CI recompilation. Release artifacts publish from tagged CI builds, not the repo tree.

### 7. Demand-window enforcement

The linter hard-fails a compiled `-single` file whose static demand estimate falls outside ~100–150% of the lane, unless the timeline's `meta:` declares the calibration demand class — an explicit, reviewable exemption. Estimates are printed for every file either way.

## Invariants (the test suite's charter)

- Same timeline + same library commit + same seed ⇒ byte-identical canonical output.
- A one-entry diff between two timelines changes only that entry's compiled events.
- `-native` and `-single` variants of one timeline differ only in declared-scalable fields.
- Compiled output validates against `dataset/schema/workload.schema.json`; the schema-declared linter invariants (event ordering, id uniqueness, FORK ⇔ spawn_table, channel resolution) are enforced.
- Registry subset lint (every `dataset/sources.yaml` id in `docs/references.md`), provenance tags, locator patterns, `meas-pending` freeze gate — per building-plan §6.
